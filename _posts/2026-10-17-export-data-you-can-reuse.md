“ဒေတာတွေ ပြန်ထုတ်လို့ရလား?”

“ရပါတယ်။ Excel Export ပါပါတယ်။”

Software တစ်ခုကို ရွေးချယ်ချိန်မှာ ဒီအဖြေကို ကြားရရင် စိတ်ချသွားနိုင်ပါတယ်။ ဒါပေမယ့် ထုတ်လာတဲ့ဖိုင်ကို တကယ်ဖွင့်ကြည့်ပြီး မိမိလိုအပ်တဲ့အတိုင်း ပြန်သုံးနိုင်သလားဆိုတာပါ စစ်ဖို့ လိုပါတယ်။

**ဖတ်လို့ရတဲ့ Report ရရှိခြင်းနဲ့ အခြားစနစ်မှာ ဆက်သုံးနိုင်တဲ့ Data Export ရရှိခြင်းက မတူပါဘူး။**

### နမူနာ — ဖောက်သည်စာရင်းနဲ့ အော်ဒါစာရင်း ထုတ်ကြည့်မယ်

ဖောက်သည်စာရင်းဖိုင်မှာ အမည်နဲ့ ဖုန်းနံပါတ် ပါတယ်။ အော်ဒါစာရင်းဖိုင်မှာလည်း ဖောက်သည်အမည်နဲ့ ဝယ်ယူတဲ့ပမာဏ ပါတယ်ဆိုပါစို့။

နာမည်တူ ဖောက်သည်နှစ်ယောက် ရှိရင် အော်ဒါက ဘယ်သူနဲ့ ဆိုင်သလဲ?

အမည်ပြောင်းထားရင် စာရင်းဟောင်းနဲ့ ဘယ်လိုချိတ်မလဲ?

ဖိုင်နှစ်ခုလုံးမှာ တူညီတဲ့ Customer ID ပါနေရင် ဆက်နွယ်မှုကို ပြန်ချိတ်နိုင်ပါတယ်။ အမည်တစ်ခုတည်းနဲ့ ချိတ်ဖို့ ကြိုးစားရင်တော့ မှားယွင်းနိုင်ပါတယ်။

| စာရင်း | ပြန်ချိတ်ဖို့ လိုတဲ့အချက် |
|---|---|
| ဖောက်သည် | Customer ID |
| အော်ဒါ | Order ID၊ Customer ID |
| အော်ဒါအတွင်း ပစ္စည်းတစ်ကြောင်းချင်း | Order ID၊ Product ID၊ အရေအတွက်၊ ယူနစ် |
| ပစ္စည်း | Product ID၊ ပစ္စည်းအမည်၊ ယူနစ်အဓိပ္ပာယ် |

ဒီ ID တွေက စနစ်အတွင်း မူလ record ကို သတ်မှတ်ပေးတဲ့ တည်ငြိမ်တဲ့အမှတ်တွေ ဖြစ်သင့်ပါတယ်။ Export တစ်ကြိမ်လုပ်တိုင်း ပြောင်းသွားတဲ့ row number နဲ့ မတူပါဘူး။

### Export ကောင်းတစ်ခုမှာ ဘာတွေ စစ်သင့်သလဲ?

**၁။ စာရင်းအပြည့် ရသလား။** လက်ရှိစာမျက်နှာပေါ်က record တွေပဲလား၊ filter နဲ့ ကိုက်တဲ့စာရင်းအားလုံးလားဆိုတာ ရှင်းရပါမယ်။ လုပ်ငန်းဒေတာအပြည့် လွှဲယူဖို့ဆိုရင် ပုံမှန် listing export ထက် သီးခြားလုပ်ဆောင်မှု လိုနိုင်ပါတယ်။

**၂။ အသေးစိတ်နဲ့ ဆက်နွယ်မှု ပါသလား။** အော်ဒါစုစုပေါင်းပဲ ပါပြီး အထဲကပစ္စည်းတစ်ကြောင်းချင်း မပါရင် နောက်စနစ်မှာ မူလအော်ဒါကို အပြည့်ပြန်မရနိုင်ပါဘူး။

**၃။ တန်ဖိုးရဲ့ အဓိပ္ပာယ် ရှင်းသလား။** Status က 1 ဆိုတာ အတည်ပြုပြီးတာလား၊ ပို့ပြီးတာလား? Amount က ဘယ်ငွေကြေးလဲ? ရက်စွဲနဲ့အချိန်က ဘယ် timezone လဲ? Column အမည်နဲ့အဓိပ္ပာယ်ကို ရှင်းထားတဲ့ Data Dictionary တစ်ခုက အထောက်အကူဖြစ်ပါတယ်။

**၄။ ပူးတွဲဖိုင်တွေ ဘယ်လိုရမလဲ။** ဓာတ်ပုံ၊ PDF နဲ့ အထောက်အထားတွေကို အကောင့်ဝင်မှ ဖွင့်လို့ရတဲ့ link သာ ပေးထားရင် အကောင့်ပိတ်ပြီးနောက် ဆက်သုံးနိုင်မနိုင် စစ်ရပါမယ်။ ဖိုင်တွေကို သီးခြားထုတ်ယူပြီး ဘယ် record နဲ့ဆိုင်သလဲဆိုတာ ပြန်ချိတ်နိုင်ဖို့ လိုပါတယ်။

**၅။ ဖိုင်ဖွင့်တဲ့အခါ တန်ဖိုးတွေ မပြောင်းသွားဘူးလား။** မြန်မာစာ၊ ရှေ့ဆုံးသုညပါတဲ့ ဖုန်းနံပါတ်နဲ့ ရှည်တဲ့အမှတ်တွေကို နမူနာစစ်ပါ။ ဖိုင်ရဲ့ မူလတန်ဖိုး မှန်ပေမယ့် ဖွင့်တဲ့ application က နံပါတ် ဒါမှမဟုတ် ရက်စွဲအဖြစ် အလိုအလျောက်ပြောင်းဖတ်နိုင်လို့ Import သတ်မှတ်ချက်လည်း အရေးကြီးပါတယ်။

### Export ရတာနဲ့ စနစ်အသစ်ထဲ တိုက်ရိုက်ထည့်လို့ရပြီလား?

မဖြစ်မနေတော့ မရသေးပါဘူး။

စနစ်နှစ်ခုရဲ့ Field၊ Status၊ ယူနစ်နဲ့ စည်းမျဉ်းတွေ မတူနိုင်လို့ Mapping နဲ့ Validation လိုပါသေးတယ်။ Export ကောင်းတစ်ခုက ဒီအလုပ်ကို စစ်ဆေးလုပ်ဆောင်နိုင်ဖို့ အခြေခံပေးတာပါ။

ဥပမာ စနစ်ဟောင်းက ပစ္စည်းပမာဏကို ဘူးနဲ့သိမ်းပြီး စနစ်အသစ်က တစ်ခုချင်းနဲ့ သိမ်းတယ်ဆိုရင် ID ချိတ်ရုံနဲ့ မပြီးပါဘူး။ ဘူးတစ်ဘူးမှာ ဘယ်နှခုပါသလဲဆိုတာပါ သိဖို့ လိုပါတယ်။

### လုပ်ငန်းအတွက် စမ်းသပ်ချက်သေးသေးတစ်ခု

သီးခြားစမ်းသပ်နေရာမှာ နမူနာဖောက်သည် ၃ ယောက်၊ အော်ဒါ ၅ ခုနဲ့ ပူးတွဲဖိုင်တချို့ ထည့်ကြည့်ပါ။

ပြီးရင် Export လုပ်ပြီး—

- Customer ID နဲ့ Order ID သုံးလို့ ဆက်နွယ်မှု ပြန်ချိတ်နိုင်သလား။
- Record အရေအတွက်နဲ့ အော်ဒါအသေးစိတ်တွေ ကိုက်သလား။
- မြန်မာစာ၊ ဖုန်းနံပါတ်နဲ့ ရက်စွဲတွေ မှန်သလား။
- ပူးတွဲဖိုင်ကို download လုပ်ပြီး သက်ဆိုင်ရာစာရင်းနဲ့ ပြန်ချိတ်နိုင်သလား။
- ခွင့်ပြုထားတဲ့ ဒေတာအကျယ်အဝန်းအတိုင်းသာ ထုတ်ပေးသလား။

ဆိုတာ စစ်နိုင်ပါတယ်။ Data Export က အချက်အလက်များစွာ ထုတ်ယူနိုင်တဲ့လုပ်ဆောင်ချက်ဖြစ်လို့ ဘယ်သူထုတ်နိုင်သလဲ၊ ဘယ်သူ့စာရင်းတွေ ထုတ်နိုင်သလဲဆိုတာပါ သတ်မှတ်ထားဖို့ လိုပါတယ်။

### မစောင့်သင့်တဲ့အချိန်

ဝန်ဆောင်မှုရပ်မယ့်နေ့မှ Export ကိစ္စ စမေးတာထက် စတင်အသုံးပြုချိန်ကတည်းက ညှိထားတာ ပိုကောင်းပါတယ်။

ထုတ်ပေးမယ့် ဒေတာအကျယ်အဝန်း၊ ဖိုင်ပုံစံ၊ လုပ်ဆောင်ချိန်နဲ့ ကုန်ကျစရိတ်ရှိမရှိတို့ကို ရှင်းထားပါ။ စာရင်းတွေ ထုတ်နေစဉ် ပြောင်းလဲမှုတွေ ဆက်ဖြစ်နေရင် ဖိုင်တစ်ခုနဲ့တစ်ခု အချိန်တူအခြေအနေကို ကိုယ်စားပြုနိုင်မနိုင်လည်း ညှိရပါမယ်။

Export ကို Backup နဲ့လည်း မရောသင့်ပါဘူး။ ဒေတာတချို့ ပြန်ထုတ်နိုင်တာနဲ့ စနစ်တစ်ခုလုံးကို ပြန်ဖွင့်နိုင်တဲ့ Backup ရှိပြီလို့ မဆိုနိုင်ပါဘူး။

**ဒီနေ့လုပ်ကြည့်ရန် —** နမူနာ Export ဖိုင်တစ်ခုကို ဖွင့်ပြီး “ဒီဖိုင်တွေနဲ့ မူလစာရင်းရဲ့ ဆက်နွယ်မှုကို ပြန်တည်ဆောက်နိုင်သလား” လို့ မေးကြည့်ပါ။ မရှင်းတဲ့ Column နဲ့ ပျောက်နေတဲ့အချက်တွေကို စာရင်းချပါ။
