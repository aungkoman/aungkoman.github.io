စနစ်အသစ်က အလုပ်လုပ်ကောင်းပေမယ့် ထည့်ထားတဲ့ဒေတာ မမှန်ရင် report ကို ယုံကြည်လို့မရနိုင်ပါဘူး။ ဒေတာဟောင်းပြောင်းထည့်ခြင်းကို project အဆုံးမှ အလျင်စလိုလုပ်တာမျိုး ရှောင်သင့်ပါတယ်။

ဥပမာ ပစ္စည်းစာရင်းမှာ “ရန်ကုန်ရုံး”၊ “Yangon” နဲ့ “YGN Office” ဆိုပြီး တည်နေရာတစ်ခုကို နာမည်သုံးမျိုးနဲ့ မှတ်ထားနိုင်ပါတယ်။ အလုံးအရေအတွက် တူပေမယ့် တည်နေရာအလိုက် report ထုတ်တဲ့အခါ စာရင်းကွဲသွားနိုင်ပါတယ်။

### ပြောင်းထည့်မယ့် data ကို ဒီလိုစစ်ပါ

1. အမည်နဲ့ code သတ်မှတ်ပုံ တူညီအောင်လုပ်ပါ။
2. ထပ်နေတဲ့ customer၊ asset နဲ့ supplier ကို ခွဲပါ။
3. မဖြစ်မနေလိုတဲ့ field တွေ ပြည့်မပြည့် စစ်ပါ။
4. ရက်စွဲ၊ ငွေကြေး၊ ယူနစ်နဲ့ opening balance ကို အတည်ပြုပါ။
5. စမ်းပြောင်းပြီး record အရေအတွက်နဲ့ စုစုပေါင်းကိန်းဂဏန်းကို နှိုင်းပါ။

မသိတဲ့ data ကို အလိုအလျောက် ခန့်မှန်းဖြည့်တာထက် “အတည်ပြုရန်လို” ဆိုပြီး သီးခြားထားခြင်းက ပိုတိကျပါတယ်။ စာရင်းအမှားကို Developer တစ်ဦးတည်းက ဆုံးဖြတ်မပြင်ဘဲ လုပ်ငန်းဘက်က တာဝန်ရှိသူ အတည်ပြုရပါမယ်။

**ဒီနေ့လုပ်ကြည့်ရန် —** ဒေတာနမူနာအနည်းငယ်ကို ယူပြီး တကယ်ရှိတဲ့စာရွက်နဲ့ တိုက်စစ်ပါ။ ပြောင်းထည့်မယ့် ရက်နဲ့အချိန်၊ စာရင်းခေတ္တရပ်မယ့်ပုံနဲ့ မူရင်းဖိုင်သိမ်းမယ့်နေရာကို ကြိုသတ်မှတ်ပါ။
