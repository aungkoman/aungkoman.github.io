“နေ့တိုင်း backup လုပ်ထားတယ်” ဆိုတာ ကောင်းတဲ့အစပါ။ ဒါပေမယ့် အရေးပေါ်အချိန်မှာ ဖိုင်မဖွင့်ရတာ၊ password မသိတာနဲ့ အချက်အလက်တစ်ပိုင်းပျောက်နေတာမျိုး ရှိနိုင်လို့ ပြန်သွင်းစမ်းထားဖို့ လိုပါတယ်။

ဥပမာ Database ကို backup လုပ်ထားပေမယ့် invoice attachment နဲ့ ပစ္စည်းဓာတ်ပုံတွေကို မသိမ်းထားရင် စနစ်အပြည့်ပြန်မရနိုင်ပါဘူး။ Server တစ်လုံးထဲမှာ မူရင်းနဲ့ backup အတူထားရင် အဲ့ဒီစက်ထိခိုက်တဲ့အခါ နှစ်ခုစလုံး ထိနိုင်ပါတယ်။

### ဆွေးနွေးထားသင့်တဲ့ မေးခွန်းများ

1. ဘာ data တွေ ပါဝင်ပြီး ဘာတွေ မပါသလဲ။
2. ဘယ်နှစ်ကြိမ်သိမ်းပြီး ဘယ်လောက်ကြာ ထိန်းထားသလဲ။
3. မူရင်းစနစ်နဲ့ သီးခြားနေရာမှာ မိတ္တူရှိသလား။
4. Backup ကို ဘယ်သူရယူနိုင်ပြီး ဘယ်သူပြန်သွင်းနိုင်သလဲ။
5. နောက်ဆုံးပြန်သွင်းစမ်းခဲ့တဲ့ရက်နဲ့ ရလဒ်က ဘာလဲ။
6. လုပ်ငန်းက ဒေတာဘယ်လောက်နောက်ကျခြင်းနဲ့ အချိန်ဘယ်လောက်ရပ်ခြင်းကို ခံနိုင်သလဲ။

ပြန်သွင်းစမ်းတာကို production data ပေါ်မှာ တိုက်ရိုက်မလုပ်သင့်ပါဘူး။ သီးခြားစမ်းသပ်နေရာမှာ restore လုပ်ပြီး နမူနာ record၊ ဖိုင်နဲ့ report ကို စစ်နိုင်ပါတယ်။

**ဒီနေ့လုပ်ကြည့်ရန် —** “Backup ဘယ်မှာလဲ” ဆိုတာထက် “ဒီ backup နဲ့ စနစ်ကို နောက်ဆုံးဘယ်နေ့က ပြန်ဖွင့်စမ်းခဲ့သလဲ” လို့ မေးပါ။ ရလဒ်ကို အချိန်၊ data အကျယ်အဝန်းနဲ့ တွဲမှတ်ထားပါ။
